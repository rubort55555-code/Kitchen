# Кухня

Приложение для телефона: что есть дома, что приготовить, сколько продуктов съедено и сколько пропало — в количестве и в рублях.

- Работает без интернета, данные хранятся только в телефоне.
- Бесплатно: без регистрации, платных сервисов и ключей.
- Подбор блюд — кнопкой «Спросить Claude» (открывает обычный чат с готовым запросом).

**Открыть:** https://rubort55555-code.github.io/Kitchen/
На iPhone: Safari → «Поделиться» → «На экран „Домой“».

**Android (тестовая сборка):** страница Releases → «Кухня для Android (тестовая сборка)» → скачать `kitchen.apk` на телефон и открыть. Новая версия ставится поверх старой, данные сохраняются.

**iPhone (тестовая сборка, пока без аккаунта Apple):** страница Releases → «Кухня для iPhone (тестовая сборка)» → `kitchen-unsigned.ipa`. Ставится с компьютера через [Sideloadly](https://sideloadly.io): подключить iPhone кабелем, перетащить файл, войти своим Apple ID. С бесплатным Apple ID приложение работает 7 дней, потом его нужно поставить заново поверх старого — данные сохраняются.

## Для разработчика

- `npm install` и `npm run build` — сборка в папку `dist/`.
- Публикация автоматическая: GitHub Actions собирает и выкладывает на GitHub Pages при каждом изменении в ветке `main`.
- Обновление баз без новой версии приложения: сборка кладёт на сайт `recipes.json` (с частями) и `catalog.json` со временем сборки. Приложение из магазина при запуске и при возврате в него (не чаще раза в час) берёт их с сайта, если они там не старее встроенных; без интернета — встроенные. Новые рецепты добавляются, исправленные — обновляются, если человек их не менял, а убранные из базы — удаляются из телефона, если в них нет ничего личного (избранное, оценка, фото, заметка, история готовки, правки) и их нет в меню (`src/lib/baseSync.ts`, список всех рецептов базы — поле `ids` в `recipes.json`); избранное, оценки, фото и заметки не трогаются. Чтобы обновить рецепты у всех — изменить `recipes/*.txt` (или справочник в `src/lib/catalog*`) и влить в `main`.
- Пищевая ценность рецептов (КБЖУ, витамины, минералы на порцию и % нормы члена семьи): `src/lib/recipeNutrition.ts`, блок `src/components/RecipeNutrition.tsx`. Состав продуктов — Fineli Release 18 (THL, Финляндия, лицензия CC BY 4.0; выписка `tools/fineli-values.json`, обновляется `node tools/fineli-extract.mjs <папка Fineli_Rel18_open>`) и USDA SR28 (общественное достояние, пакет `fda-nutrient-database`) для продуктов и показателей, которых нет в Fineli; сопоставление ингредиентов (поля `ndb`, `fineli`, `override` — значения по ГОСТ и маркировке) и вес бытовых мер — `tools/nutrition-map.jsonl`, таблица для приложения — `npm run composition` → `src/lib/compositionData.json`. Новый ингредиент в рецептах нужно добавить в карту (проверяет `tests/recipe-nutrition.test.ts`). Расчёт ориентировочный: без потерь витаминов при готовке, масло для жарки учитывается целиком; йод — по Fineli (у продуктов только из USDA йода нет), соль нейодированная.
- В базе только рецепты в формате технологической карты (этапы, шаги с огнём, временем и признаками готовности; выход, посуда, активное время, готовность, типичные ошибки, подача, хранение). Новые рецепты добавляются сразу в этом формате. Правила — `tools/REWRITE.md`, проверка — `npm run check-recipes`.
- iOS: папка `ios/` (Capacitor, Swift Package Manager). `npm run ios` — собрать и скопировать в проект iOS; приложение собирает `.github/workflows/ios.yml` на Mac в GitHub, без подписи. Тексты разрешений (камера, фото) — `ios/App/App/Info.plist`.
- Android: приложение-обёртка на Capacitor (папка `android/`, настройки — `capacitor.config.json`). `npm run android` — собрать и скопировать в проект Android; APK собирает `.github/workflows/android.yml`. Подпись `android/app/kitchen-test.keystore` — только для тестовых сборок, для Google Play будет отдельный ключ в секретах GitHub. Особенности приложения (меню «Поделиться» вместо скачивания файла и т. п.) — `src/lib/native.ts`.
- Оформление «Сад»: цвета трёх тем (светлая, тёмная, «солнце» — контрастная для яркого света) — переменные в начале `src/styles.css`, тема выбирается атрибутом `data-theme` у `<html>`. Выбор темы — `src/lib/theme.ts`, пороги яркости (30% и 80% с запасом, чтобы не мигало) — `src/lib/themeRules.ts`, экран Ещё → Оформление. Режим «по яркости экрана» — только в приложении: свой модуль Capacitor `Brightness` (`android/.../BrightnessPlugin.java`, регистрация в `MainActivity.java`; для iOS — в `ios/App/App/SceneDelegate.swift`). Шрифт Manrope (SIL OFL 1.1) лежит в `public/fonts/`, подключён в `src/index.html` — работает без интернета.
- Проверки: `tests/theme.test.ts` (пороги оформления), `tests/logic.test.ts` (правила, разбор ответа Claude), `tests/nutrition.test.ts` и `tests/e2e_nutrition.py` (питание), `tests/barcode.test.ts` (распознавание штрихкодов, разбор Open Food Facts), `tests/recipe-nutrition.test.ts` (пищевая ценность), `tests/basesync.test.ts` и `tests/e2e_content.py` (обновление рецептов и справочника с сайта), `tests/e2e.py` и `tests/e2e_barcode.py` (сценарии в браузере, Playwright), `tests/e2e_receipts.py` (качество распознавания чеков на тестовых «фото» разных магазинов — фон, наклон, тень, размытие, бледная печать; чеки в `tests/receipts/`).
- Чеки: распознавание на телефоне (Tesseract.js, только русский — с английским путаются похожие буквы), перед ним фото обрезается по краю чека и выравнивается (`src/lib/ocr.ts`); разбор строк понимает форматы «количество x цена», «цена x количество», сумму отдельной строкой, «Кол-во … Цена … Сумма», коды товаров, строки НДС и оплаты, исправляет латиницу и похожие символы в цифрах и сверяет цены с «ИТОГО» (`src/lib/receipt.ts`); слова с 1–2 неверными буквами заменяются ближайшими знакомыми из справочника продуктов и частых слов в чеках — только при уверенном совпадении (`src/lib/ocrWords.ts`). Название продукта из чека сохраняется полным («Хлеб заливной»), вид по справочнику (`kind`, «Хлеб») — для места, срока и рецептов; справочник ищет вид прежде всего по первому слову названия. Точнее всего — «Распознать с Claude»: запрос `CLAUDE_RECEIPT_PROMPT`, человек прикрепляет фото в чате, ответ разбирает `parseClaudeReceipt` (`src/lib/receipt.ts`).
- Штрихкоды: своё распознавание EAN-13/EAN-8/UPC-A (`src/lib/barcode.ts`), поиск товара в Open Food Facts через бесплатный API (`src/lib/off.ts`). Данные © участники Open Food Facts, лицензия ODbL — источник указан рядом с данными.
- Питание (проба): `src/lib/nutrition.ts` — основной обмен (Миффлин — Сан-Жеор), расход по дневнику дня (занятия по времени, код и MET из 2024 Adult Compendium — `src/lib/activities.ts`, ~290 занятий), ИМТ и талия (ВОЗ), нормы БЖУ, клетчатки, витаминов и минералов (МР 2.3.1.0253-21). Экран `src/screens/Nutrition.tsx`.
- Дневник питания: записи о съеденном (`Meal` в `src/lib/types.ts`, хранилище `meals` в IndexedDB — версия базы 2) с пищевой ценностью на съеденное (`n` — ключи как в `recipeNutrition.ts`). Чистая логика — `src/lib/diary.ts` (рецепт × порции, продукт × граммы из справочника состава, товар по штрихкоду из Open Food Facts, своё блюдо, суммы за день, остаток до нормы из `planFor()`, подсказки, недавнее), действия — `src/lib/store.ts` (`addMeals`, `deleteMeals`, `repeatDay`, `addWater`, `syncPlanMeal`: отметка «приготовили» в меню пишет блюдо в дневник, снятие отметки — убирает), экран — `src/screens/Diary.tsx` (карточка «Сегодня съедено» на главной, окно «Дневник питания» с водой, витаминами и минералами против нормы МР, окно «Что вы съели»). Дневник входит в копию данных. Проверки: `tests/diary.test.ts`, `tests/diary-store.test.ts`, `tests/e2e_diary.py` (Python Playwright; браузер задаётся переменной `CHROMIUM`).
- Сочетания нутриентов и кофеин: `src/lib/interactions.ts` (правила и источники, напитки с кофеином, подсказки), блок «Сочетания и усвоение» в дневнике, вкладка «Напиток» при записи еды. Литература и рекомендации по поиску для расчёта биодоступности — `literature/nutrient-interactions/` (README.md — что найдено и на чём стоят правила, SEARCH_GUIDE.md — что искать дальше). Проверка: `tests/interactions.test.ts`.
